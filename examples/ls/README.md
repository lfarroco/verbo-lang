# Verbo → `ls` end-to-end example

This directory is the complete output of the exercise: a natural-language spec
for a small `ls` CLI, sharpened through Verbo's pipeline, then implemented from
the refined spec by an "AI coding tool" (the intended consumer of Verbo's
output).

```
test/ls/                    ← the Verbo spec project (plain Markdown, natural language)
  main.md                   ← project context + CLI features
  models/entry.md           ← the ListingEntry data model
  models/options.md         ← the CLI options data model
  types.verbo.ts            ← generated by `verbo check` (internal verification)
  .verbo/validate.ts        ← generated constraint assertions
  .verbo/clarifications/    ← audit trail (3 interview sessions, JSONL + log)
  clarifications.json       ← remaining ambiguity report (10 edge cases)

examples/ls/
  ls.ts                     ← the implementation, generated from the refined spec
  ls_test.ts                ← one test per spec behavior (12 tests)
```

## The Verbo loop (what was run)

```bash
# 1. Extract models from prose, generate types, validate with deno check
deno run -A main.ts check   --dir test/ls -a deepseek
# 2. Find ambiguities (15 found)
deno run -A main.ts clarify --dir test/ls -a deepseek
# 3. Resolve them interactively; answers are written back into the .md files
deno run -A main.ts interview --dir test/ls -a deepseek --recheck
# 4. Repeat: round 2 (9 more), round 3 (10 more, all deep edge cases)
```

Three interview rounds: **15 → 9 → 10** ambiguities, each round finding deeper,
more specific questions (long-format columns → symlink semantics → tie-breaker
interactions). The loop is iterative by design (`docs/DESIGN.md`: "ambiguity as
compile error"); you stop when the remaining questions are below your risk
tolerance.

## Spec → code mapping

Every behavior in `ls.ts` is traceable to a sentence that survived the interview
loop:

| Spec sentence (refined `.md`)                                                     | Implementation                                                 |
| --------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| `-a` includes hidden entries (names starting with a dot)                          | `opts.showHidden` filters dot-prefixed names                   |
| The special entries `.` and `..` are never listed                                 | `collectDir` skips both unconditionally                        |
| `-l`: type char (`d`/`f`), size, `YYYY-MM-DD HH:MM` local, name only (never path) | `formatEntry`                                                  |
| A directory always reports size 0, never a computed total                         | `buildEntry` sets `size = 0` for dirs                          |
| For a symbolic link, the size of the link itself (not its target) is reported     | `Deno.lstatSync` (no symlink following)                        |
| A symbolic link is listed as a file (`isDirectory` false) and is never followed   | `Deno.DirEntry.isDirectory`; recursion only descends real dirs |
| Sorted by name using case-sensitive ordering                                      | `compareNames` byte-order                                      |
| `-t` newest first; equal timestamps tie-break by name ascending                   | `sortEntries("modified")`                                      |
| `sortBy "none"` = filesystem order                                                | `sortEntries("none")` no-ops                                   |
| `-r` reverses whichever sort is active (not traversal order)                      | `sortEntries(...).reverse()` per directory                     |
| `-R`: header line per directory path, then entries; dir itself never listed       | `walk()`                                                       |
| Unreadable subdirectory → error to stderr, continue                               | `walk()` returns non-fatal                                     |
| Error reading the top-level directory is fatal, exit 1                            | `list()`/`walk()` fatal path                                   |
| Error message to stderr, exit code 1 for all error conditions                     | `ListingResult.exitCode` → `Deno.exit`                         |
| Path is a regular file → list that single file as one entry (even with `-R`)      | `singleFileEntry`                                              |
| `-a` + `-R`: hidden dirs traversed and printed with same header format            | `walk` naturally includes them                                 |

## Implementation choices for the 10 remaining clarifications

Round 3 ended with 10 open questions. The implementation pins each one:

1. **Size units in `-l`** — bytes, always.
2. **`.`/`..` with `-a`** — still never listed (spec already says so).
3. **`-r` + `-t` tie-breaker** — reverse applies to the whole sequence.
4. **Error message format** — `ls: <verb> '<path>': <os message>`.
5. **Single-file `path` field** — `name` = basename, `path` = provided path.
6. **`-l` + `-R` output** — per-directory long lines (type/size/date/name).
7. **`-t` across `-R`** — sorting is per-directory listing, not global.
8. **`-R` starting-dir header** — always printed (path as given).
9. **`-t` dir vs file ordering** — no directories-first rule; pure time sort.
10. **Section separators in `-R`** — blank line between directory sections.

## Running it

```bash
deno test -A examples/ls/ls_test.ts
deno run -A examples/ls/ls.ts -a -l -R .
```
